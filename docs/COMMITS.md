## 二、每个阶段在做什么

| 阶段 | 主题 | 涉及概念 | 学习要点 |
| --- | --- | --- | --- |
| 0 | 仓库基线与项目约定 | Git 初始化、`.gitignore`、公开 / 私有内容分离、中文提交规范 | 静态博客可以把「代码公开、内容私有」做在同一套目录里：用 `.gitignore` 排除内容路径，代码照常协作 |
| 1 | 主题骨架与设计令牌 | 主题目录结构、`layout.ejs` 包装机制、CSS 变量、界面文案 i18n | Hexo 会用主题的 `layout.ejs` 自动包住 `index.ejs`、`post.ejs` 等视图，页面模板只写内容区 |
| 2 | 双语内容模型与语言路由 | front-matter 内容模型、渲染前过滤器、站点级生成器覆盖、URL 前缀识别 | 双语不是 Hexo 的内置能力：Hexo 只按 URL 前缀识别界面语言，内容归属要自己用 `lang` 加生成器过滤实现 |
| 3 | 频道分页 | 同名生成器覆盖、分页路由约定、partial 复用、摘要 helper | 分页不必依赖 `hexo-pagination`：把文章切片后按「第 1 页是频道地址、第 N 页是 `page/N/`」生成路由即可 |
| 4 | 文章排版 | Prism 服务端高亮、文章资产目录、相邻文章查找、译文入口 | 文章页的 `page.path` 是路由路径，文章集合里的 `path` 是 permalink，跨来源比较路径要先归一化 |
| 5 | 分类与标签 | 同名生成器覆盖、分页逻辑复用、分类标签路径、按语言统计 | 官方分类标签生成器把两种语言混在一起，注册同名 `category` / `tag` 生成器即可替换成按语言拆分的版本 |
| 6 | 归档 | 同名生成器覆盖、按年月分组、模板内分组渲染 | 分组不必写进生成器：生成器负责筛选与排序，分组交给模板 helper，职责更清楚 |
| 7 | 站点资料与关于页 | `_data/` 数据文件、双语字段取值、模板读取数据 | 写死在主题里的站点信息要全部搬到数据文件：主题负责「怎么显示」，数据负责「显示什么」 |
| 8 | 交互与响应式 | 导航高亮 helper、`aria-current`、`:focus-visible`、`prefers-reduced-motion`、响应式断点 | 高亮当前栏目不能只比路径：频道文章归属于频道页，要结合 `section` 与语言判断 |
| 9 | 部署链路 | `rsync` 同步、release 目录 + `current` 软链、原子切换与回滚、发布前示例内容检查 | 静态站点发布最重要的是切换的原子性：先传完新版本再切软链，出问题只需把软链指回旧版本 |
| 10 | 项目文档与提交索引 | 文档与实现对齐、用 `git ls-files` 导出公开文件做新环境验证 | 文档里引用的路径与提交号都要实际校验，否则文档会悄悄过期 |
| 11 | 相册频道 | `photos` 频道扩展、内容即文章、堆叠封面、无依赖灯箱与键盘交互 | 相册不需要新体系：把它当成一篇带 `photos` / `captions` 字段的文章，复用频道、路由与相邻文章逻辑，只新增展示层 |
| 12 | 旧站内容迁移 | 只读复制、路径保持、`.gitignore` 校验、示例内容清理 | 私有内容不在 Git 里，迁移只能靠文件复制与文档留痕；迁移后要顺手清掉公开示例，否则 `content:init` 会把它们补回来 |

## 三、这一路踩过的坑

- **`page.posts` 不一定是 Hexo 集合**：生成器传普通数组时调用 `.toArray()` 会报错，用 `as_list` helper 统一处理。
- **`before_post_render` 对页面也会执行**：它不只作用于文章，给数据补 `section` 时要先用 `slug` 区分。
- **路径有两种写法**：路由路径带 `index.html`，permalink 不带，比较前先归一化。
- **bash 3.2 的多字节问题**：`$变量（中文` 会被解析成变量名的一部分，紧跟非 ASCII 字符时要写成 `${变量}`。
- **`url_for` 会编码中文**：中文分类路径会变成 `%E5%B7%A5%E5%85%B7`，服务器解码后正好对应中文目录。
- **流程坑**：新增功能应当先出小方案并更新 PLAN，再动代码；阶段编号或范围的调整要经确认，不能由实施方自己顺延。

## 四、分支与回看方式

- 每个阶段的短分支都保留着，可以当书签用：`git switch feat/channels` 就能回到阶段 3 的代码。
- 想看某一阶段改了什么：

```bash
git show 2a9262c            # 看阶段 3 的功能提交
git switch feat/channels    # 直接切到阶段 3 的分支
```

- 觉得分支太多想清理时，逐个删除已合并的分支即可：

```bash
git branch -d feat/theme-skeleton
git push origin --delete feat/theme-skeleton
```
